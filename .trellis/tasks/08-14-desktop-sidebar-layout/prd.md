# 重构桌面侧栏布局

## Goal

将桌面客户端主界面改为接近 Codex 的固定侧栏结构：补齐包含品牌和快捷入口的左上导航，用稳定、克制的边缘分栏取代当前左右两块悬浮圆角卡片，同时保持 OpenAgentSeal 现有业务行为不变。

## Background

- 当前 `DesktopApp.vue` 将来源工作区、主聊天区和右侧工具区放在同一个可变三栏容器中。
- 左侧来源工作区和右侧工具面板使用大圆角、外边距、阴影和玻璃背景，视觉上像悬浮卡片；用户明确希望改为 Codex 风格的正常贴边面板。
- 现有会话创建、选择和管理继续保留在原有流程中，本任务不迁移或重写会话数据逻辑。
- 当前工作目录由设置存储和工作目录 API 管理；来源工作区由 `WorkspaceManager` 管理。现有 `WorkspaceManager` 的内容和行为保持不变，但必须嵌入固定左侧栏下半部分，不得在聊天区旁再形成独立一列。
- 浏览器、对话与运行、沙盒、设置已有独立打开函数，可作为新侧栏或右侧工具区的入口复用。
- 当前未提交的高 DPI 响应式修复是本任务的兼容基线，不得回退。

## Requirements

### R1 固定左侧导航

- 桌面宽屏下显示固定、全高、贴左边缘的侧栏，不使用悬浮卡片式外边距、大圆角或投影。
- 左侧栏顶部必须包含品牌区、收起入口和“新会话”主入口，并承载现有能力的快捷导航。
- 第一版顶部快捷导航确定为：新会话、对话与运行、浏览器、沙盒、设置；按钮仅调用既有处理函数，不新增“拉取请求、站点、已安排”等业务。
- 左侧栏下半部分直接承载现有工作区选择、搜索、文件/目录/Web/路径工具和内容列表；工作区可在左栏内展开或收起，但不得从聊天区挤出第二列。
- 侧栏应支持收起，收起后仍保留恢复入口，避免长期占用聊天空间。

### R2 中央聊天区

- 主聊天区保持内容主导，不因左栏或右栏产生额外的悬浮卡片外框。
- 顶部智能体切换、模型选择、输入区和底部状态能力继续可用。
- 新建会话后，中央聊天内容与当前会话状态继续按既有逻辑同步。

### R3 贴边工具面板

- 来源工作区不再是聊天区中的工具面板；其完整内容归入左侧栏下半部分。
- 右侧浏览器/运行/沙盒面板改为贴边、直角或小圆角的标准工具面板。
- 面板之间用边线和可拖动分隔条区分，不使用大面积外边距、22px 圆角和悬浮阴影。
- 右侧工具面板保留关闭、全屏和调整宽度能力。
- 左侧栏展开工作区内容并同时打开右侧工具面板时，不得出现第三列或横向裁切。

### R4 响应式与 DPI

- Windows 100%、150%、200% 缩放下布局保持可用。
- 约 945×640 CSS 像素时应优先保持可用的桌面布局，不复现沙盒被压到下方并裁切的问题。
- 更窄视口可折叠左栏或改为抽屉，并允许工具内容滚动；页脚、输入框和面板关键操作不得被裁掉。

### R5 可维护性与可访问性

- 优先拆出专用桌面侧栏组件，避免继续扩大 `DesktopApp.vue` 的模板与样式职责。
- 所有图标按钮必须保留可读的 `title` 或 `aria-label`，键盘焦点态清晰。
- 不改变会话、工作目录、来源工作区和工具面板的前后端行为与数据契约。

## Acceptance Criteria

- [ ] 启动桌面客户端后，左侧显示固定导航，左上包含品牌、收起、新会话及现有工具入口，左下直接包含完整工作区内容。
- [ ] 点击“新会话”继续调用现有新会话流程；其他入口继续打开对应的现有面板或设置。
- [ ] 工作区在左侧栏内部展开，聊天区 DOM 中不存在独立来源工作区列或来源工作区拖动分隔条。
- [ ] 右侧工具面板贴边显示，无现有 22px 大圆角、外部留白和悬浮阴影。
- [ ] 左栏工作区保留现有工作区选择、搜索、文件/目录/Web/路径、列表与文件操作能力。
- [ ] 浏览器、运行、沙盒、设置入口仍可到达，已有核心操作不丢失。
- [ ] 1280×860@1x、945×640@2x 和窄屏场景下，无页面横向溢出，输入区、页脚及工具关键内容可见或可滚动到达。
- [ ] 左栏工作区与右侧工具面板同时打开时，布局不会形成三列或横向裁切。
- [ ] 前端类型检查、生产构建、响应式布局测试和关键交互测试通过。

## Out of Scope

- 仿制 Codex 尚不存在于 OpenAgentSeal 的“拉取请求、站点、已安排”等完整业务功能。
- 新增历史会话列表、项目树、多工作目录切换等信息架构或业务能力。
- 修改后端会话、工作区或沙盒协议。
- 本轮重新设计设置页内部内容。
